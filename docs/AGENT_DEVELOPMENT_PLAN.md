你是本项目的开发 Agent。按本文件推进现有原型，交付可运行、可安装、可验证的增量，不停留在方案建议或伪代码。

先读根目录 AGENTS.md、README.md、DEVELOPMENT_PLAN.md，再读本文件和 AGENT_PROGRESS.md。完整需求与性能阈值以 POLISH_MASTER_PLAN.md 为准；本文件负责说明如何实施与验收，不另行降低标准。

- Godot 4.7.2、GDScript、Android Compatibility；离线单机。
- 一主角、一关、三类敌人、一 Boss、两武器；不新增联网、广告、内购、账户或成长系统。
- 自制美术、音乐、音效，保留源文件、生成/制作记录和资产清单；禁用无来源游戏素材。

- 修改玩法后执行 `python3 tools/manage.py test`；修改 UI/渲染后实际查看截图，动画必须连续检查。
- 临时脚本、引擎、密钥和原始日志放 work/，交付排除密钥。
- 模拟验证、单设备实测、多设备实测、未测试分别记录；逻辑模拟不算真机性能。

### 3.2 如何选择下一项

1. 阅读台账“当前断点”，检查上一轮失败项和未完成的实现。
2. 优先修复阻断、高等级缺陷；随后选择依赖满足的最早任务 ID。
3. 默认沿 G0→G1→G2/G3→G4→G5 推进。M3 的场景/UI可在 M1 样板可用后推进；音效同步需等待对应 M2 事件契约稳定。
4. 如 G1/G2 因外部硬件检查未验收，可继续不依赖该检查的实现，但阶段仍未通过；不得进入最终验收完成状态。
5. 一个工作批次围绕一个行为或表现闭环，避免同时重写控制、碰撞、资源和全部场景。
6. 一个任务完成后继续推进下一个可执行任务，不为常规实现反复请示。只有用户要求停下、必要外部条件缺失且无独立工作可做等情况才交接。
7. 长任务及时写台账，不能只依赖聊天上下文；进度更新说明发现、剩余风险和下一项验证。

## 4. 实现契约

以下为待落地的工程约定，接入时保持现有玩法回归。

### 4.1 逻辑与表现分离

- 物理步维护位置、速度、生命、弹丸、攻击节奏与关卡状态。
- 表现层只读取状态及消费事件，不能在 `_draw()` 中扣血、生成伤害或决定胜负。
- 暂停时停止游戏状态与战斗表现计时；菜单自身所需动画可以继续。
- 死亡/胜利的逻辑结果先确定，演出按阶段播放。演出资源缺失不能导致无法结算。
- 统一 reset/退出流程，清空弹丸、触点、特效、震动、音效及状态计时。

### 4.2 角色状态与枪口

逻辑状态建议包括地面待机/跑动、上升/下落、下蹲、死亡；受击为有时限的表现状态，瞄准和开火作为可组合参数。死亡优先级最高；受击不能永久覆盖移动或吞掉输入。

维护一个双方共用的枪口查询接口，输入至少包括角色位置、朝向、姿态和瞄准方向，输出枪口世界位置与单位方向。名称由实现决定，但弹丸、枪火、持枪贴图和调试标记必须读同一套数据。

- 左右平射、斜上、正上、蹲姿和空中分别定义锚点。
- 镜像只翻转需要的局部坐标，不能把世界位置重复镜像。
- 坐标转换集中处理；相机位移只影响显示。
- 动画帧共用一致缩放基准，脚底锚点固定；不能把每帧外包框强制拉成同一高度。

### 4.3 事件、资源与预算

- 用明确事件或信号表达开火、命中、落地、死亡、Boss 阶段变化；保存必要位置、方向、类型，不保存将被销毁对象的悬空引用。
- 建议新增的职责目录：scripts/player/、scripts/enemies/、scripts/boss/、scripts/effects/、scripts/level/、scripts/ui/；按任务需要创建，不先造空框架。
- 建议资源目录：resources/animations/、resources/enemies/、resources/encounters/；优先使用 Resource，已有 JSON 可在明确导出规则下保留。
- 保持音效与特效有界，超限优先丢装饰，不丢关键危险弹丸。
- 诊断功能默认关闭，不让普通玩家在游戏流程中看到工程选项。

## 6. 验证与构建操作手册

### 6.1 常规命令

在项目根目录执行：

```sh
python3 tools/manage.py test
python3 tools/manage.py run
python3 tools/manage.py build
```

`run` 为交互运行；桌面环境需要 GUI 权限时按工具要求申请。若现有引擎不存在，先查看 tools/manage.py 与环境配置，不擅自替换 Godot 版本。需要下载依赖再走对应权限流程。

安装前使用实际 SDK 路径查询设备：

```sh
/Users/huangbo/Library/Android/sdk/platform-tools/adb devices -l
python3 tools/manage.py install --serial <本次确认的设备序列号>
```

上述 SDK 路径来自当前工作环境，换机器时重新发现；历史 JER-AN20 序列号不代表当前连接状态。`<...>` 是占位符，不可原样执行。多设备必须显式指定序列号。

遇到沙箱阻止 ADB、本机服务或 GUI 时，使用工具的权限申请参数重试，不换其他途径绕过限制。安装失败先保留现有包与数据，禁止默认卸载或清除用户存档。

### 6.2 必须检查的结果

- 测试：检查退出码、RESULT 和 SCRIPT ERROR，历史 20/20 不能复制成新结果。
- 渲染：实际打开截图；连续动作必须查看录像或实际运行，检查脚底、比例、枪口、透明边缘。
- 构建：检查本轮日志与新 APK，不能在失败后把旧 APK 当新包安装。
- 安装：检查 Success 和启动结果，再核对手机画面；安装成功不能代表战斗/性能通过。
- 性能：记录采样工具、时间粒度、单位、设备和场景；不从单个 FPS 标签推断 P95/P99。
- 资源：运行时 JSON、字体许可等进入导出；source_assets/、work/ 不进入 APK。

### 6.3 验证分类

| 修改类别 | 必要验证 |
| --- | --- |
| 玩法、输入、状态机、敌人、Boss、碰撞、重构 | manage.py test；重要新行为补有意义测试；相关实际操作 |
| UI、美术、特效、摄像机 | 真实渲染截图检查；有动画则连续检查；适用真机路径复验 |
| 音频 | 实际听检；状态切换与声道上限检查 |
| 性能 | 同设备、同路线前后采样；最终真实20分钟；对象/内存与帧耗时一起检查 |
| 文档、清单 | 链接、任务引用、清单字段及状态一致性；无需为文档修改运行游戏测试 |

不为了凑数量增加镜像实现的测试。新测试优先覆盖枪口方向、状态切换、一次性结算、暂停清理、输入释放和资源生命周期等真实风险。

## 8. 更新与交接协议

### 8.1 完成一个任务后

1. 更新 AGENT_PROGRESS.md 对应状态、验证范围、证据与当前断点。
2. 新资产更新 ASSET_MANIFEST.csv，补源图、脚本/提示词和许可记录。
3. 新验证更新 TEST_REPORT.md；新问题更新 KNOWN_ISSUES.md。

5. 用户可见说明包含具体变化、验证、限制和 APK 安装状态；不要声称未执行的测试。

### 8.2 无法完整验收时

外部设备、手柄、真实人工操作或权限缺失：把对应任务置为 WAITING_EXTERNAL，写明缺什么、如何补测、哪些实现已完成。继续其他不依赖该条件的任务。不能把等待条件变成跳过验收，也不能为每个常规实现另起确认流程。

如需要用户实操，只请求无法自动完成的具体步骤，例如“持续三指操作5分钟并提供操作反馈”；自动注入三个输入状态最多只能证明逻辑组合，不代表触摸硬件通过。

### 8.3 交接模板

```text
当前阶段/任务：
已实现内容与文件：
最后一次实际验证（命令、日期、结果）：
设备/构建/APK哈希：
截图/录像/性能证据：
剩余缺陷与复现步骤：
外部条件缺口：
下一项动作（具体到文件/函数/资源）：
```

不要写“基本完成，下次继续优化”一类无法接手的断点。
