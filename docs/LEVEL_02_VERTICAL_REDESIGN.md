# 第二关重设计：暴雨水坝·纵向攀登

版本：已批准设计v1.0 / 2026-11-04（Asia/Shanghai）  
状态：**用户已明确批准开发；0.3.1阶段实施见[验证报告](evidence/vertical/REPORT.md)。**  
适用版本：对当前0.3.0第二关的结构重设计；第一关保留。  
关联：[原第二关计划](LEVEL_02_AGENT_DEVELOPMENT_PLAN.md)、[执行台账](LEVEL_02_PROGRESS.md)。

## 1. 本次需求与设计结论

用户不喜欢当前第二关中大量横向跑动，期望类似其所描述的魂斗罗攀登体验：角色主要向上推进，左右换侧、跳台和射击交替发生。

本方案以这项体验描述为准，不用原作的版本或关号争论替代需求，也不复刻原版地图与素材。

**新的第二关是一座从坝底一直打到坝顶的纵向关卡。屏幕向上移动，角色在屏幕内左右选择落脚点；整条主线不再向右铺开。**

需要保留的体验是“看上方→处理威胁→跳到左/右高台→继续登高”。左右移动是为了攀登、躲避和争取射击角度，不再是沿长走廊赶路。

初稿为设计审阅稿；用户随后明确“这个方案可以，请帮我开发吧”，已授权更新地图、镜头、敌人、Boss坐标、构建及手机调试。0.3.0可恢复基线保存在work/vertical/baseline/。

## 2. 当前版本为什么不符合预期

当前第二关世界长度约13,800逻辑单位，其中河道约4,200、坝顶约4,900，另有横向Boss接近区；主要攀升只发生在x=4,200～7,000、净高度约1,440的中段。

此外，中段平台基本按“每级向右100、向上60”连续排列。虽然角色在上升，但整体仍向右平移，缺少在同一竖井内左右折返、重新观察上方路线的感觉。

| 当前安排 | 新方案 |
| --- | --- |
| 长河道→一段上坡→长坝顶→Boss | 坝底起步→连续分层攀登→顶部Boss |
| 镜头大量横移 | 游玩世界固定一屏宽，镜头只做纵向跟随 |
| 连续向右上方铺台阶 | 左、中央、右平台组交替，数跳后换侧 |
| 去不同横向位置找节点开门 | 节点放在上行路线旁，顺路射击产生战术收益 |
| 关卡完成感依赖向右走了多远 | 完成感来自“已经爬过哪些层，上方还剩哪些区域” |

## 3. 必须满足的结构约束

以下是本次改版的核心验收要求，不是可选建议。

1. **一屏宽世界。** 逻辑画布仍为960×540，普通游玩世界x约0～960，主要站立范围x=80～880。不再设置延伸到屏幕外的横向主线。
2. **纵向镜头。** 主线与Boss场镜头x固定，登高时向上跟随。不能用换成很长的右上斜坡代替纵向关卡。
3. **绝大多数主线平台转换都要上升。** 非Boss必经平台转换中，至少85%有明显高度增加；其余只用于短距离换侧或休息。这个比例按平台转换计算，不以角色累计x/y位移计算。
4. **没有长地面赶路。** 非Boss主线连续必要地面跑动不超过160逻辑单位；超过时必须重新布置邻接平台，而非加敌人掩盖空跑。
5. **有节奏地左右换侧。** 通常连续2～4次跳跃后调整推进方向，少数宽松教学/收束段可例外；不能从头到尾只按住右键攀登。
6. **左右两侧通过中间平台连接。** 不要求一次从左墙跳到右墙，也不新增二段跳、蹬墙跳或攀爬键。
7. **失误可挽回。** 不强制向上自动卷屏，不因角色掉出屏幕就判死，不清空仍可回落的平台。
8. 保持两关、两个Boss、一名主角、三类普通敌人、两武器、离线单机；不扩展新系统。

## 4. 整体布局：一座竖向水坝，而非四条横向走廊

工作名称仍为「暴雨水坝 / 雷闸行动」，视觉主题保持已经确认的暴雨、泄洪水幕、钢结构和青色HUD。

首轮结构预算：一屏宽，净攀升约3,120逻辑单位，约六个屏幕高度；分六个攀登区，顶部再接同屏Boss战。高度与平台数是编排起点，不是为了凑时长的硬指标。

```text
                    水坝顶部
          ┌────────────────────────┐
          │        潮汐守卫        │  同屏决战，不再横向跑去找Boss
          ├────────────────────────┤
          │ F：右侧 → 左侧 → 中央 │  最后一轮换侧，上到主闸平台
          │            ↑           │
          │ E：左侧 ↗ 中央 ↗ 右侧 │  顺路破坏供能节点、关闭危险
          │            ↑           │
          │ D：中央 → 右 → 左     │  交错火力与分组登高
          │            ↑           │
          │ C：中央 → 右 → 中左   │  宽安全台、补给、短暂缓冲
          │            ↑           │
          │ B：右 → 中央 → 左 → 中│  瀑布两侧换位，先看再跳
          │            ↑           │
          │ A：中央 → 左 → 右     │  安全教学，建立左右向上节奏
          ├────────────────────────┤
          │    坝底入口 / 出生台   │  出生即能看到第一组上行平台
          └────────────────────────┘
```

这是路线关系示意，不是最终平台坐标图。横向箭头代表通过若干个中间高台逐步换侧，不能理解成一条长地板。

### 4.1 六区段设计

以H表示从坝底累计攀升的高度，H越大越接近坝顶。

| 区域 | 高度草案 | 玩家体验 | 地形与威胁 | 换侧关系 |
| --- | --- | --- | --- | --- |
| A 坝底支架 | H=0～480 | 先学会左右选台，再处理第一名敌人 | 宽入口、低风险固定平台；前3跳没有机关；上层侧面步兵 | 中央起步，偏左后转向右侧 |
| B 泄洪水幕 | H=480～1,080 | 观察对面火力，在瀑布两侧逐级换位 | 左右井壁、中间落脚台；一处喷口先单独预警再与交火组合 | 右→中央→左→中央 |
| C 中层维护台 | H=1,080～1,560 | 稍微放松、补给、重新观察上层 | 一个宽休息台，随后短平台组；一台侧置炮塔 | 中央→右→中左 |
| D 交叉火力层 | H=1,560～2,160 | 在左右高台间改变射击角度 | 分组步兵、炮塔与无人机；先处理上层，再跳向新落点 | 中左→右→左 |
| E 供能支架层 | H=2,160～2,640 | 登高同时摧毁侧面目标，降低机关压力 | 两个供能节点都在主线上可射击的位置；关闭各自电区 | 左→中央→右 |
| F 主闸上行层 | H=2,640～3,120 | 使用已学动作完成最后换侧，抵达Boss前平台 | 少量组合威胁、宽顶台、Boss前检查点；不再加入新机关 | 右→左→中央 |

初始主线约50～60次有效平台转换，按地形组合验证后可增减。表中的左右关系是编排约束，不要求每层复制相同的“S形楼梯”。各区通过平台组、留白、敌人站位和机关用途产生差别。

### 4.2 一个典型平台组应该怎么玩

以B区的一组上行为例：

1. 玩家在右侧宽台看到中央稍高平台，以及左侧更高的敌人。
2. 可先斜上射击，也可先跳到中央的安全平台再寻找角度。
3. 中央平台提供短暂停留机会；不会一落地就被碰撞伤害或喷口命中。
4. 再向左上跳到另一组平台，处理侧面炮塔或无人机。
5. 登上左侧宽台后，镜头露出下一组向右上方的路线。

玩家应经常产生“下一步该跳左边还是右边、先打哪个方向”的判断，而不是只按住一个方向连续跳。

## 5. 跳跃手感与地形规范

沿用当前移动、单段跳、跳跃缓冲、离台宽限和三向射击，不改变已改善的摇杆与跳跃/射击按钮布局。

| 项目 | 第一轮建议 | 原因 |
| --- | --- | --- |
| 相邻必经平台高差 | 常规40～60，最大64 | 留出操作余量，保留现有跳跃参数 |
| 相邻落脚中心水平变化 | 常规60～100，通常不超过110 | 换侧通过多跳实现，避免一跳横跨整屏 |
| 普通必经落脚面宽 | ≥144 | 触屏修正空间足够 |
| 换向/战斗/休息台宽 | 240～360；兜底台可更宽 | 可以站稳、转向和瞄准，无需精准踩边 |
| 同高缺口净间隙 | 通常≤80，最大96 | 仅作少量变化，不变成横版跨坑关 |
| 换侧组连接 | 每组2～4跳，再调整方向 | 避免每跳都急转向，也避免全程单向阶梯 |

这些是初始设计边界，必须验证高差、横向距离与落脚宽度的组合；不能分别满足三个数值就判定跳跃可达。敌人、装饰支架和栏杆不能占用实际落脚区。

避免三类布局：只改高度但一直向右的台阶；从一侧宽台跑大半屏才能起跳；连续极窄平台上同时要求转向、射击和极限跳跃。

### 5.1 失误与回落

- 每2～3个小平台下方安排一个可见兜底支撑，尽量将失误限制为掉回几层，而不是整段重爬。
- 兜底台也是实际可踩平台，可从下方跳过；不能做看不见的救援地板。
- 角色掉回已有平台时，镜头允许向下跟随，保留重新登高的路线。
- 只有进入明确标示的世界落水/关外区域才触发坠落恢复。判断基于世界危险区，不基于当前屏幕边缘。
- 保留当前扣1HP并恢复安全位置的规则：即使处于受击无敌也要恢复位置，最后1HP则进入正常死亡重试。
- 安全恢复点必须能站稳，不能在坑边、喷口、电区或敌人出生点；回落和恢复都不重刷得分、拾取或节点奖励。

## 6. 敌人与机关：威胁来自上层，给玩家观察时间

继续使用步兵、炮塔、无人机，不新增普通敌种。敌人主要分布在玩家上方和斜上方，但必须进入可观察范围并完成预警后才攻击。

| 敌人/机关 | 新布局用途 | 公平性要求 |
| --- | --- | --- |
| 步兵 | 站在上层侧台，推动玩家先射击或换侧接近 | 不站在唯一落脚点正中央，不在角色落地瞬间接触扣血 |
| 炮塔 | 侧壁固定火力点，形成可读射线 | 不从HUD遮挡区或屏外开火；攻击期间有安全停留台 |
| 无人机 | 穿过两层之间的空间，打破纯静态射击 | 活动范围受当前平台组约束，不追着玩家贯穿整关 |
| 喷口 | 让玩家决定何时起跳、是否先换一侧 | 先展示预警，再安排组合；不能覆盖所有可达落点 |
| 通电区 | 提供可跳过或可关闭的局部危险 | 保留至少一条正常步枪/普通跳跃可走的路线 |

教学层同时有效敌人建议≤2，中后段通常2～3，局部上限4。新关总活动普通敌人仍不得超过6；越层后的旧敌人按二维距离和区域状态清理，不无限叠加。

不要求每一层清空全部敌人才能上去。玩家可以主动登高绕过部分普通威胁，但不能因此出现无限追兵、刷分或检查点串状态。

### 6.1 节点不再负责制造横向绕路

取消“先沿长河道跑到继电器，再去坝顶左右找两个节点”的主线结构。

- 坝底继电器可保留为顺路射击教学对象，不再封锁整关入口。
- 两个供能节点移到E区上行路线旁，从必经宽台能用平射或斜上射击命中。
- 初版将节点设为**可选战术目标**：破坏后关闭对应电区并给一次奖励；不破坏也有明确可执行的跳跃路线。
- 节点不再决定Boss是否激活，不通过隐藏的y坐标限幅阻止登高。这样即使跳过节点，也不会到顶后被迫下楼找开关。
- 不新增停下来交互的按钮、开关谜题或远距离收集任务。

## 7. 镜头、视野与HUD

### 7.1 纵向镜头

- 世界一屏宽，镜头x固定；角色左右换侧时不横向摇摆。
- 主要依据已经站稳的更高平台推进镜头，带小范围死区和平滑，避免每次跳起/下落都上下晃动。
- 起跳前应看到下一处落点；站稳后至少能观察上方1～2层，重要攻击预警不能位于HUD后方。
- 玩家靠近上方观察边缘时允许提前上移，以免下一层突然从屏外出现。
- 回落到下方支撑时允许镜头下移，不做只进不退的强制上卷；不上演“屏幕追着角色判死”。
- 区域转换通过高度和二维区域判断，不以x坐标跨线切换。

第一轮构图目标：稳定站立的角色脚底通常位于画面下半部约y=330～370，上方留给下一跳与敌人；起步、回落和Boss构图可例外。

### 7.2 HUD与主题延续

保留青色战术HUD、湿冷蓝灰水坝、琥珀机关预警、现有摇杆和错层动作键。视角是原有侧视2D，不改成俯视、伪3D或攀墙模拟。

主目标文案改为当前层名称与“继续攀登 / 抵达主闸层”，可附简洁的纵向进度提示；不再以横向距离或每组清敌数量作为主要进度感。进度用已抵达的最高关键层记录，短暂回落不显示进度突然倒退，但真实位置与镜头仍正常下降。

上方平台边缘、落脚区、角色和敌弹优先于瀑布与雨雾。瀑布作为分层背景，不把跳台画成水幕里无法辨认的暗影。普通版与低特效版都保留清楚预警，不能靠闪屏识别危险。

## 8. 检查点与关卡失败

设置四个持久于本次关卡运行的检查点：坝底起点、C区维护台入口、E区入口、顶部Boss前。每个检查点有可见安全平台和简短反馈，不新增永久中途续关系统。

| 检查点 | 作用 | 恢复要求 |
| --- | --- | --- |
| CP-0 坝底 | 全新开局 | 满血、步枪、初始机关与得分 |
| CP-1 维护台 | 不因中段失误重爬教学层 | 恢复已提交的遭遇/拾取/节点状态与得分 |
| CP-2 供能层入口 | 练习后半段组合攀登 | 不重复前段奖励，机关从安全初态恢复 |
| CP-3 主闸平台 | 单独练习Boss | 完整恢复Boss双臂与核心，清旧弹/预警/特效 |

检查点以稳定ID和区域/落地状态触发，允许新检查点x小于前一个。不能继续使用当前“cp.x大于旧cp.x就更新”的条件。

死亡后仍满血、步枪重试，在检查点后可选位置安排散弹机会，普通步枪必须可解。旧版第二关的进程内检查点不跨地图复用；既有设置、正式关卡解锁与最高分保留。

## 9. 顶部Boss：保留潮汐守卫，取消长距离接近区

爬上最后一组中央平台后，直接看到主闸决战场，Boss前检查点就在下方安全台。无需再向右跑数屏。

优先复用已经制作的双臂闸机主体、分层武装、核心及音效，调整其位置、预警和战场构图，不新增第三个Boss。

- Boss位于顶部场地上方偏右的坝墙，角色从下方/左侧抵达，开场展示上方威胁。
- Boss主体、双臂、角色及至少一处撤离区域应同时可见，镜头继续固定x。
- 基本阶段保留“双臂武装→核心暴露→超载”；弱点必须可由平射/斜上射击命中，不能要求目前没有的向下射击或新跳跃能力。
- 可设置少量固定高低台提供射击角度，但不强制站在窄台硬吃攻击。若某部位只能由高台命中，必须验证该高台的到达与撤离路线。
- 扇形弹与锁定攻击保留明确预告，锁定后不追踪；冲击波和落点打击需重新核对与高低台的关系，不直接搬旧战场坐标。
- Boss阶段允许同屏短距离左右回避，这是战斗走位，不是横向赶路。不得用另一条长横版走廊连接到Boss。
- 普通敌人、外围机关在Boss战时关闭并清理；死亡后仅结算一次。

## 10. 节奏与难度目标

首要目标是让用户一开始就明确感觉“这一关在往上打，并且需要左右换侧”，其次才是总时长。

暂沿用4～6分钟作为熟悉操作后完整成功通关的软目标，不包含暂停和失败重试。这个目标当前没有验证；新布局完成后需至少3次真人完整成功记录，再决定节奏调整。

每区采用“登高小组→局部交火→换侧→安全台”的变化节奏，避免52次完全相同的跳台。前段教观察落点，中段教处理高低火力，后段组合已有动作，不突然加入新操作。

若试玩仍偏短，优先增加有独立判断价值的平台组/敌人站位变化；若偏长，优先删重复段与过密停顿。禁止靠强制等待、堆Boss血量、重复清屏或把竖井无意义拉高凑时间。
